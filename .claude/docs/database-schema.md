# Database Schema — V1__init.sql

PostgreSQL 18.3. Schema is owned by Flyway. Migration file:
`backend/src/main/resources/db/migration/V1__init.sql`.

Status fields use `VARCHAR + CHECK` constraints so they map directly to JPA
`@Enumerated(EnumType.STRING)` without native PG enum types. Surrogate keys are
`BIGINT GENERATED BY DEFAULT AS IDENTITY`. All timestamps are `TIMESTAMPTZ DEFAULT now()`.

## Tables

### roles
`id` PK · `name` UNIQUE
Seeded with `CENTRAL_ADMIN`, `HUB_PICKER`.

### users
`id` PK · `name` · `email` UNIQUE · `password_hash` · `role_id` FK→roles · `status` · `created_at`
- `status` CHECK in (`ACTIVE`, `INACTIVE`, `SUSPENDED`), default `ACTIVE`
- index on `role_id`

### warehouses
`id` PK · `warehouse_code` UNIQUE · `warehouse_name` · `address`

### picker_warehouse_mapping
Composite PK `(picker_id, warehouse_id)`
- `picker_id` FK→users · `warehouse_id` FK→warehouses
- index on `warehouse_id`

### products
`sku` PK (VARCHAR, natural key) · `name` · `barcode` · `unit`
- index on `barcode`

### shelf_locations
`id` PK · `warehouse_id` FK→warehouses · `sku` FK→products · `aisle` · `bay` · `shelf` · `location_code`
- UNIQUE `(warehouse_id, sku)` — one shelf row per product per warehouse
- `location_code` example format: `Aisle_A-Bay_04-Shelf_2`
- index on `sku`

### orders
`id` PK · `order_number` UNIQUE · `customer_id` (VARCHAR since V3) · `warehouse_id` FK→warehouses · `picker_id` FK→users (nullable, since V4) · `status` · `version` · `created_at`
- `status` CHECK in (`PENDING`, `ASSIGNED`, `PICKING`, `COMPLETED`, `DISPATCHED`), default `PENDING`
- `version` INTEGER default 0 (for JPA optimistic locking later)
- indexes on `warehouse_id`, `status`

### order_items
`id` PK · `order_id` FK→orders · `sku` FK→products · `item_name` · `ordered_quantity` · `picked_quantity` · `status`
- `picked_quantity` default 0
- `status` CHECK in (`PENDING`, `PICKED`, `SKIPPED`), default `PENDING`
- indexes on `order_id`, `sku`

### pick_sessions
`id` PK · `order_id` FK→orders · `picker_id` FK→users · `start_time` · `end_time` · `status`
- `status` CHECK in (`OPEN`, `IN_PROGRESS`, `COMPLETED`, `CANCELLED`), default `OPEN`
  - (status values were not specified in the brief; these are sensible defaults — revisit when picking logic lands)
- indexes on `order_id`, `picker_id`

### pick_logs
`id` PK · `session_id` FK→pick_sessions · `sku` · `quantity` · `location` · `scan_time` · `scan_id` (UNIQUE, nullable; idempotency key, since V5)
- `sku`/`location` are denormalized scan snapshots (no FK by design — logs are immutable history)
- index on `session_id`

### audit_logs
`id` PK · `user_id` FK→users · `action` · `order_id` (nullable) · `sku` (nullable) · `location` (nullable) · `timestamp`
- indexes on `user_id`, `order_id`

## V2__auth.sql

### refresh_tokens
`id` PK · `user_id` FK→users · `token_hash` UNIQUE (sha256 hex, 64 chars) · `expires_at`
· `revoked` (default false) · `created_at`
- Stores only the SHA-256 hash of opaque refresh tokens. Supports logout (revoke) + rotation.
- index on `user_id`

## V3__orders_customer_id_varchar.sql
Alters `orders.customer_id` from `BIGINT` to `VARCHAR(64)` (BRD 3.2 — Customer_ID is a string).

## V4__picker_workflow.sql
- Adds `orders.picker_id` (nullable, FK→users) — set when a picker claims an order.
- Creates `picker_active_warehouse(picker_id PK→users, warehouse_id→warehouses, selected_at)` —
  the picker's active warehouse for the (stateless) session.

## V5__pick_logs_scan_id.sql
Adds `pick_logs.scan_id VARCHAR(64)` + a UNIQUE index (nullable; NULLs distinct) — optional
scan idempotency key for BRD 3.3 Scan-to-Pick.

## FK / dependency order (creation order in migration)
roles → users → warehouses → picker_warehouse_mapping → products → shelf_locations
→ orders → order_items → pick_sessions → pick_logs → audit_logs
